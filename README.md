# Active Silence in Beethoven: Low-Energy Pause Strategies

This repository contains the materials behind **"Active Silence in Beethoven: Low-Energy Pause Strategies in the Grave of the Pathetique,"** a late-breaking demo paper prepared for **ISMIR LBD 2026**. It includes the analysis code, extracted timing tables, figures, and the source manifest for the study set verified on July 21, 2026.

The CSV files in `data/` are the verified outputs used in the current draft. If you rerun the detector on newly downloaded audio, or under a different `ffmpeg` build, a few pause boundaries may land slightly differently.

Current dependency note: earlier local history mentioned a nonexistent Pillow pin. The maintained requirement is now `Pillow>=11.0,<12`; regenerate figures with the current `requirements.txt`, not that obsolete commit message.

## What Is Not Here

No audio files are included. The WAVs linked through ATEPP are copyrighted commercial recordings, so this repository only includes code, extracted features, figures, and provenance metadata. If you want to rebuild the results, use `data/manifest.csv` together with the documented ATEPP and YouTube links, then place the audio in one local directory. The shipped detector-derived tables were regenerated from a single verified PCM directory so that `events.csv` and `pause_boundaries_source.csv` use the same measured boundaries.

## Fast Reproduction Without Audio

The main descriptive statistics and Figure 1 can be reproduced directly from the shipped CSV files. No audio download is needed for this path:

```bash
python3 -m pip install -r requirements.txt
python3 code/03_analysis.py
python3 code/04_figures.py
python3 code/05_significance.py
```

## Full Audio-Dependent Reproduction

Before running anything, install `ffmpeg` and put the local audio files in one directory. The scripts look for filenames such as `AB.wav`, `DB.wav`, or the pianist name, across `wav`, `mp3`, `flac`, `m4a`, and `aiff`.

```bash
python3 -m pip install -r requirements.txt
export AS_AUDIO_DIR="/absolute/path/to/local/audio"
python3 code/01_detect.py --audio-dir "$AS_AUDIO_DIR" && python3 code/02_normalize_rerun.py --audio-dir "$AS_AUDIO_DIR" && python3 code/05_boundaries.py --audio-dir "$AS_AUDIO_DIR" && python3 code/06_threshold_sweep.py --audio-dir "$AS_AUDIO_DIR" && python3 code/03_analysis.py && python3 code/04_figures.py && python3 code/05_significance.py
python3 code/07_waveform_panels.py --audio-dir "$AS_AUDIO_DIR"
```

## Data Dictionary: `data/events.csv`

- `recording_id`: short identifier used throughout the package.
- `pianist`: performer name.
- `pause`: score-referenced, order-selected Grave pause label (`P1`-`P4`).
- `d_s`: sounding duration before the detected low-energy region, in seconds.
- `d_l`: low-energy duration after decay and before the next attack, in seconds.
- `T`: total local pause interval, defined as `d_s + d_l`.
- `condition`: `source` for the source-conditioned baseline run, `peaknorm` for the `-1 dBFS` peak/gain control rerun.
- `threshold_setting`: silence-detector setting used for that row. The shipped event table uses the verified baseline `-35dB_0.10s`.

## Pause Labels

`data/pause_locations.csv` records the nominal musical targets and the actual selection rule for P1-P4. The current detector is order-selected inside an opening-window heuristic rather than audio-to-score aligned. In particular, P3 is chosen as the longest eligible late-Grave silence, so its pooled mean duration is not comparable to P1, P2, and P4 as an independent discovery.

`data/pause_boundaries_source.csv` is regenerated by `code/05_boundaries.py` when local audio is available. With the verified PCM directory used for this package, the current boundary export recovers all 68 source-condition rows. `data/pause_boundaries_failures.csv` remains part of the workflow so failed recordings are logged rather than silently repaired when another local audio directory is used.

Quality-control note: the regenerated Arrau and Fischer rows have identical P2 `d_s`/`d_l` values and near-identical P3 values. The local files used for the canonical run are distinct by filename, byte size, duration, and SHA-256 hash, so this is not caused by `resolve_audio_path` returning the same file for both recordings.

## Known Limitations

- The boundary detector uses an absolute `dBFS` threshold, so event boundaries remain sensitive to source level and mastering differences.
- The current pause labels are score-referenced but not score-aligned. Bar identity should be hand-verified or replaced by audio-to-score alignment before stronger score-localization claims.
- The peak-normalized rerun is a simple gain control to `-1 dBFS`, not integrated-loudness normalization; LUFS-based normalization is left to future work.
- `d_s` is not treated as a pure performance variable because it mixes acoustics, transfer, score texture, pedaling, and release behavior.
- P1 `d_s` can be clamped by file-head/noise-floor behavior and should be treated cautiously.
- P4 often sits close to the detector floor, so its short duration is a robust descriptive regularity but not yet a strong claim about a final caesura.
- The historical Schnabel source is documented in the manifest but excluded from the core event table because ATEPP flags the representative source as background noise.
